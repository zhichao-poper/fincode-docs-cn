什么是订阅

订阅功能

fincode 的订阅功能可定期向客户收取固定金额，所有商户均可免费使用这项基本功能。
您可通过 API 或控制面板，按指定金额和支付间隔向客户收取订阅费用。
对于持续获得收入的业务，商户可以使用订阅功能，由系统定期执行支付，无需自行实现定时处理。

订阅功能适用于定期收取固定金额。对按用量收费等每次收费金额不同或每位客户收费金额不同的情况，可以考虑使用批量支付功能。

订阅状态

fincode 的订阅会在以下状态之间转换。

状态名称状态含义说明
ACTIVE有效该订阅有效。
系统会在指定扣费日向登记订阅时指定的客户执行支付。
RUNNING处理中正在向客户执行支付。
CANCELED停止该订阅已失效，系统不会向客户收费。
INCOMPLETE失败该订阅因某种原因登记失败。
系统不会向客户收费。

查看订阅结果

订阅定期生成的收费信息，可通过サブスクリプション結果照会获取。
每次收费是否成功，可以根据对应订阅结果的ステータス (status)值判断。
在控制面板中，也可以查看由订阅生成的收费信息，对应的是扣费类型为“订阅”的支付数据。
详细规范请参阅管理订阅。

订阅重试（自动再次收费）

当卡片订阅收费遇到特定错误时，fincode 可以自动再次执行支付（重试）。

基本规范

项目规范
支持的支付方式卡片支付（※银行账户自动扣款不适用）
执行重试的间隔每隔 7 天（固定）
重试次数上限最多 3 次（固定）
设置单位按方案设置（启用：enabled ／停用：disabled）
初始设置停用（disabled）

可以通过 API 或控制面板按方案启用或停用重试。

行为规则

【设置生效时间】
重试行为遵循订阅首次扣费时的方案设置，该设置适用于该订阅的整个运行期间。

【自动重试条件】
只有订阅登记成功、状态为ACTIVE（有効），且收费时发生特定支付错误（※），才会自动重试。

以下情况发生支付错误时，订阅状态会变为INCOMPLETE（失敗），因此不会自动重试。

  • 将扣费开始日设为登记当天，登记订阅时同步执行的首次支付失败。
  • 将扣费开始日设为未来日期，登记订阅时同步执行的有效性检查失败。

※系统仅针对余额不足等在一段时间后可能成功的特定错误代码执行重试。其他错误代码导致的支付失败会显示为没有重试计划，系统不会重试。

【取消订阅时的行为】
取消已有重试计划的订阅后，即使状态变为 CANCELED（停止） ，原已计划的重试仍会执行完毕。
