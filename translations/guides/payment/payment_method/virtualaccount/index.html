使用支付方式 API 管理客户的固定虚拟账户

什么是为客户签发的固定虚拟账户

固定虚拟账户是向客户签发的长期虚拟账户。在显式删除前，虚拟账户一直保留相同的账户信息，因此可持续为同一客户提供相同的收款账户。

普通的银行转账（虚拟账户）会为每笔支付签发一次性虚拟账户。使用固定虚拟账户，则可向有长期交易的客户提供固定的收款账户。

签发的账户作为 fincode 的支付方式（Payment Method）处理。每位客户最多可登记 5 个。

使用此功能前，须申请开通 fincode 的虚拟账户支付并通过审核。
此功能为可选功能，按已签发账户数逐月收费。

支付方式状态列表

为客户签发的固定虚拟账户（支付方式）可处于以下状态。

状态名称状态说明
有效ACTIVE可以接收转账。
已停用INACTIVATED暂时停止接收转账。重新激活支付方式可恢复为ACTIVE状态。

INACTIVATED状态的账户无法接收转账。

支付方式状态转换

下表列出各操作后的状态。“－”表示没有对应的结果或操作。

操作操作前状态操作后状态
登记支付方式－有效（ACTIVE）
停用支付方式有效（ACTIVE）已停用（INACTIVATED）
重新激活支付方式已停用（INACTIVATED）有效（ACTIVE）

使用 API

登记为客户签发的固定虚拟账户

在登记支付方式（POST /v1/customers/{customer_id}/payment_methods）的请求体中，将 pay_type 设为 Virtualaccount ，即可签发固定虚拟账户并关联到指定客户。

登记成功后，响应中将包含账户信息（分行代码、账号、账户户名）。请将这些信息告知客户。

更改默认设置

客户登记了至少一个固定虚拟账户时，有且只有一个账户会设为“默认”。
在更新支付方式（PUT /v1/customers/{customer_id}/payment_methods/{payment_method_id}）中更改 default_flag ，即可切换默认账户。

停用、重新激活和删除

操作API
停用PUT /v1/customers/{customer_id}/payment_methods/{payment_method_id}/inactivate
重新激活PUT /v1/customers/{customer_id}/payment_methods/{payment_method_id}/activate
删除DELETE /v1/customers/{customer_id}/payment_methods/{payment_method_id}

请在停用和重新激活的请求体中指定 pay_type: Virtualaccount 。
有关 API 详情，请参阅API 参考（支付方式）。

使用为客户签发的固定虚拟账户进行支付的流程

此功能有两种入账场景。

场景 1：转账时自动生成支付

客户向账户转账后，fincode 会自动生成一条支付信息，其条件为pay_type = Virtualaccount且状态为売上確定（CAPTURED）。每次转账都会生成支付信息，可在每次入账时通过控制面板或 Webhook 确认。

因向客户固定虚拟账户转账而生成的支付信息会设置 use_static_virtual_account: true 。

场景 2：预先创建支付信息，再通过为客户签发的固定虚拟账户核销

预先创建支付信息，在客户向账户转账时完成该笔支付。

  1. 使用登记支付创建支付信息，并在pay_type: Virtualaccount）。
  2. 执行支付（PUT /v1/payments/{id}）的请求体中为 payment_method_id 指定客户固定虚拟账户的 ID。
  3. 支付信息会转为支払い待ち（AWAITING_CUSTOMER_PAYMENT），并等待向指定账户转账。
  4. 客户向该账户转账后，支付信息会转为売上確定（CAPTURED）。
对同一账户处于支払い待ち（AWAITING_CUSTOMER_PAYMENT）状态的支付信息，同一商户内同时只能创建一条。

Webhook 事件

操作客户固定虚拟账户或转账完成时，会发送以下 Webhook 事件。

事件名称事件类型发送时间
customers.payment_methods.created登记支付方式为客户签发的固定虚拟账户登记时
customers.payment_methods.updated更新支付方式默认设置更新时
customers.payment_methods.inactivated停用支付方式账户停用时
customers.payment_methods.activated重新激活支付方式账户重新激活时
customers.payment_methods.deleted删除支付方式账户删除时
payments.virtualaccount.complete转账完成向账户转账并生成支付信息时（生产环境）
payments.virtualaccount.complete.stub转账完成（测试）向账户转账并生成支付信息时（测试环境）

customers.payment_methods.*该事件的载荷包含支付方式对象（为客户签发的固定虚拟账户）。
payments.virtualaccount.*该事件载荷与普通固定虚拟账户支付 Webhook 采用相同格式发送。
