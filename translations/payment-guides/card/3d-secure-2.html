使用 3D Secure 2.0 认证

鉴于卡片支付欺诈造成的损失急剧增加，日本经济产业省在《信用卡安全指南》中宣布，要求日本国内所有电商特约商户在 2025 年 3 月底之前引入 EMV 3-D Secure（3D Secure 2.0）。使用 fincode 必须引入 EMV 3-D Secure。

每次支付时输入卡片信息

  1. 客户选择信用卡支付作为支付方式。
  2. 商户执行 fincode 的登记支付。
  3. 商户执行 fincode 的令牌 JS。
  4. 商户发送令牌。
  5. 商户执行 fincode 的执行支付。
  6. 商户将客户重定向至执行支付响应中的 redirect_url。
  7. 客户的浏览器与 fincode 自动交互并执行 3D Secure 认证。
  8. 如果触发验证挑战，页面会自动跳转至发卡机构提供的页面进行本人认证。
  9. 3D Secure 认证完成后，客户会自动返回商户网站。
    1. 如果 3D Secure 认证失败或发生错误等，将不执行授权，并重定向至执行支付时指定的 return_url_on_failure。
    2. 3D Secure 认证后支付成功时，将通过 POST 重定向至执行支付时指定的 return_url。
    3. 3D Secure 认证后支付失败时，将重定向至执行支付时指定的 return_url_on_failure。

使用 fincode 中已登记的卡片，无需输入卡片信息

可以使用令牌或卡片登记 JS，利用预先为客户登记的卡片信息完成支付，无需每次输入卡片信息。

  1. 客户选择信用卡支付作为支付方式。
  2. 商户执行 fincode 的登记支付。
  3. 商户使用与客户账户关联的客户 ID 执行获取卡片列表。
  4. 商户让客户从获取到的卡片信息列表中选择卡片。
  5. 商户指定所选卡片的 ID 和客户 ID，执行执行支付。
  6. 商户将客户重定向至执行支付响应中的 redirect_url。
  7. 客户的浏览器与 fincode 自动交互并执行 3D Secure 认证。
  8. 如果触发验证挑战，页面会自动跳转至发卡机构提供的页面进行本人认证。
  9. 3D Secure 认证完成后，客户会自动返回商户网站。
    1. 如果 3D Secure 认证失败或发生错误等，将不执行授权，并重定向至执行支付时指定的 return_url_on_failure。
    2. 3D Secure 认证后支付成功时，将通过 POST 重定向至执行支付时指定的 return_url。
    3. 3D Secure 认证后支付失败时，将重定向至执行支付时指定的 return_url_on_failure。

进阶：从零开始实现包含 3D Secure 认证的卡片支付

在 fincode 的卡片支付中，与 3D Secure 认证相关的页面跳转和回调处理，会以访问 redirect_url 为触发条件自动执行。不过，商户也可以自行实现 3D Secure 认证所需的全部 API 调用、回调处理和重定向处理，从而完全自定义支付体验。

请求执行支付时，不指定 return_url，而是指定 tds2_ret_url，响应中便会返回 acs_url，而不是 redirect_url。当购买者访问该 URL 时，将启动完全自定义的 3D Secure 认证。

  1. 客户选择信用卡支付作为支付方式。
  2. 商户执行 fincode 的登记支付。
  3. 商户执行 fincode 的令牌 JS。
  4. 商户发送令牌。
  5. 商户执行 fincode 的执行支付。fincode 登记 3D Secure 2.0 认证并返回结果。
  6. 商户将客户重定向至 3D Secure 认证初始化 URL（acs_url）。在 3D Secure 认证初始化 URL（acs_url） 中，3D Secure 服务器会初始化 3D Secure 2.0 认证，然后重定向至商户返回 URL（tds2_ret_url）。
  7. 商户接收发往商户返回 URL（tds2_ret_url）的回调。
  8. 商户执行 fincode 的执行 3D Secure 认证。fincode 执行 3D Secure 2.0 认证处理并返回结果。
  9. 如果需要验证挑战，商户将客户重定向至 challenge_url，启动 3D Secure 2.0 认证挑战。
  10. 客户访问 3D Secure 2.0 认证页面。
  11. 客户输入认证信息并进行本人认证。3D Secure 服务器将客户重定向至商户返回 URL（tds2_ret_url）。
  12. 商户接收发往商户返回 URL（tds2_ret_url）的回调。
  13. 商户执行确认 3D Secure 认证结果。
  14. 商户执行 fincode 的执行认证后支付。fincode 向发卡机构执行授权处理并返回结果。
  15. 商户显示完成页面。

※重定向至 3D Secure 服务器的环节属于客户与 3D Secure 服务之间的交互，因此商户需要引导客户访问 fincode 返回的 3D Secure 认证初始化 URL（acs_url）。
在 3D Secure 认证初始化 URL（acs_url） 中会初始化 3D Secure 2.0 认证，并通过 HTTP POST 方法跳转至商户返回 URL（tds2_ret_url）。
在 3D Secure 2.0 中，根据发卡机构的判断，有时不需要显示密码输入页面。
此外，如果卡片不支持 3D Secure 2.0，可以通过设置登记支付中的不支持 3D Secure 2.0 时的操作（tds2_type），选择继续执行授权或返回错误。

来自 3D Secure 2.0 服务器的回调

通过执行支付中设置的商户返回 URL（tds2_ret_url）接收来自 3D Secure 服务器的回调，并根据回调内容决定后续处理分支。

回调会在以下时机发生。HTTP 方法为 POST。

  • 访问执行支付响应中的 acs_url 时。
    ※商户引导客户访问 acs_url（使其发生重定向），且 3D Secure 服务器完成 3D Secure 2.0 认证初始化之后
  • 验证挑战完成时。
    ※商户引导客户访问 3D Secure 2.0 认证挑战 URL（challenge_url）（使其发生重定向），且持卡人完成本人认证之后

3D Secure 服务器会向商户的商户返回 URL（tds2_ret_url）返回以下信息。

参数数据格式说明
MD查询字符串access_id
requestorTransIdapplication/x-www-form-urlencoded请求方交易 ID（不使用此值）
eventapplication/x-www-form-urlencoded事件
3DSMethodFinished：3D Secure 2.0 初始化处理已完成。请执行执行 3D Secure 认证。
3DSMethodSkipped：已跳过 3D Secure 2.0 初始化处理。请执行执行 3D Secure 认证。
AuthResultReady：请执行确认 3D Secure 认证结果。
paramapplication/x-www-form-urlencoded3D Secure 2.0 认证参数。用于执行 3D Secure 认证。

向 fincode 登记卡片信息时执行 3D Secure 认证

为客户登记卡片时，也可以执行 3D Secure 2.0 认证。
如果希望在登记卡片时的有效性检查中执行 3D Secure 2.0 认证，请使用登记支付方式。
有关 API 规范，请参阅API 参考 - 登记支付方式。

※同样用于为客户登记卡片信息的卡片登记，仅支持不执行 3D Secure 2.0 认证的情况。
有关 API 规范，请参阅API 参考 - 卡片登记。

登记卡片时，建议使用登记支付方式。
※截至 2024 年 8 月，获取、更新和删除已登记卡片信息时，请使用卡片 API。
今后计划支持通过支付方式 API 执行相同操作。

  1. 客户登记购买者信息。
  2. 商户执行 fincode 的客户登记。
  3. 商户执行 fincode 的令牌 JS。
  4. 商户发送令牌。
  5. 商户执行 fincode 的登记支付方式。fincode 登记 3D Secure 2.0 认证，并在响应中返回 3DS 认证页面 URL redirect_url。
  6. 商户将客户重定向至 redirect_url。客户与 3D Secure 服务之间会执行 3DS 认证处理。
  7. fincode 执行 3D Secure 2.0 认证处理。
  8. 如果需要验证挑战，客户与 3D Secure 服务之间会启动 3D Secure 2.0 认证挑战。
  9. 客户访问 3D Secure 2.0 认证页面。
  10. 客户输入认证信息并进行本人认证。
  11. fincode 确认认证结果。
  12. fincode 根据认证结果向发卡机构执行授权处理，并返回结果。
  13. fincode 根据授权结果，将客户跳转至成功或失败 URL。
