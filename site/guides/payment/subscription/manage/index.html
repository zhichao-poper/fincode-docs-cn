管理订阅

本页介绍如何查看订阅扣费结果，以及如何变更或取消订阅。

登记订阅

登记订阅的流程

按以下步骤创建订阅。

  1. 创建作为收费对象的客户。通过 API 操作时，请使用登记客户接口。
  2. 为收费对象登记卡片。通过 API 操作时，请使用登记卡片或登记支付方式接口。
  3. 创建方案。方案包含使用金额、支付间隔等信息。通过 API 操作时，请使用プラン登録。
  4. 指定客户 ID、收费对象、方案 ID 和扣费开始日，登记订阅后便完成创建。

　　　通过 API 操作时，请使用登记订阅接口。

登记订阅时，请以YYYY/MM/dd格式指定扣费开始日。dd所指定的日期决定每次订阅的扣费日。
例如，方案支付间隔为 2 个月，订阅扣费开始日为2023/12/15时，日程如下。

扣费日收费金额
首次扣费2023/12/15订阅指定的首次使用金额，或方案指定的使用金额
第 2 次2023/2/15方案指定的使用金额
第 3 次2023/4/15方案指定的使用金额

（此后按相同规律重复）

更改首次收费金额

fincode 的订阅可设置首次使用金额（以及首次税费和运费），使首次扣费金额有别于方案设定的金额。
可借此加收初始费用，或在月中开始订阅时按天计费。通过 API 设置首次使用金额时，请在登记订阅 API中设置initial_amount。

在月末扣费

fincode 的订阅可以在指定日期扣费，也可以在月末最后一天扣费。
在登记订阅 API的请求参数中，为月末課金フラグ (end_month_flag)指定1: 月末に課金する。
也可在控制面板的“创建订阅”页面登记订阅，将“扣费时间”设置为“月末日”。
例如，方案支付间隔为 1 个月，订阅扣费开始日为2023/12/31且扣费时间设为月末时，日程如下。

扣费日收费金额
首次扣费2023/12/31订阅指定的首次使用金额，或方案指定的使用金额
第 2 次2023/1/31方案指定的使用金额
第 3 次2023/2/28方案指定的使用金额

（此后同样在每个月末收费）

订阅扣费日设为月末时，如果扣费开始日的dd值不是月末最后一天，系统会返回错误。

将订阅扣费开始日设为登记当天

如果订阅的課金開始日 (start_date)设为登记当天，系统会立即尝试首次收费。
如果首次收费成功，系统会创建对应的、状态为売上確定 (CAPTURED)的支付信息。
※如果首次收费失败，订阅会变为 失敗 (INCOMPLETED) 状态，且不适用重试设置。

当月没有指定的扣费日期

如果当月没有设定的扣费日期，例如每月 31 日扣费的订阅到了 2 月，系统会在该月最后一天收费。
例如，扣费日设为 31 日时，2 月将在 28 日扣费。

查看订阅扣费结果

登记订阅后，无论收费成功或失败，系统都会按方案指定的间隔，在登记订阅时指定的扣费日创建支付信息。
要获取订阅产生的支付列表，包括通过重试执行的支付，请在获取支付信息列表接口中用查询参数指定条件。
下表为查询条件示例。

获取支付信息列表 API 查询参数名示例含义及用途
pay_typeCard订阅的支付类型。
示例指定卡片支付的数据。
subscription_id订阅 ID。需要定位特定订阅时指定。
pay_patternsubscription扣费类型。示例指定由订阅扣费生成的支付数据。
process_date_from, process_date_to（订阅扣费日）可通过此参数指定订阅扣费日进行筛选。
status支付状态。
如果由订阅生成的支付信息处于未处理（UNPROCESSED）状态，说明收费可能失败。请查看支付信息的错误代码（error_code），如果值非空，则可判定该笔订阅收费失败。

查看重试支付时的补充事项

每次重试执行扣费时，都会新建一条卡片支付信息。根据授权结果，支付状态为销售额已确认（CAPTURED）或未处理（UNPROCESSED）。
※如果创建交易失败，则不会创建支付信息。

确认是否安排了下次重试

订阅扣费失败后，可以通过以下方法查看是否处于自动重试范围（等待下次重试）。手动再次收费前请务必确认。

1. 通过控制面板确认

在“订阅 > 卡片支付”的列表或订阅详情页查看“重试计划”栏是否显示有计划。
也可在列表右上角的搜索框中按重试计划筛选。

2. 通过 Webhook（订阅汇总）确认

可通过通知订阅批处理结果的 Webhook（recurring.card.batch）内容查看以下信息。

  • failed（失败笔数）：对应订阅扣费中支付失败的笔数。
  • retry_scheduled（安排下次重试的扣费笔数）：失败支付中被纳入自动重试的笔数。

3. 通过 API 确认

  • 获取订阅列表 API
    在查询参数中指定 is_retry_scheduled（true 或 false），即可筛选出已安排下次重试的订阅。
  • 获取订阅详情 API ／各订阅相关 API 的响应
    在订阅相关 API 的响应体中，可查看 is_retry_scheduled 字段，确认该订阅目前是否有重试计划（true：有／ false：无）。

更新或取消订阅

更改支付方式

登记订阅时指定的支付方式无法更改。
如果需要更换扣费信用卡，或因账户销户、账户变更等原因必须更换支付方式，请登记新的订阅。

更改订阅的登记内容

自首次扣费日起，无法更改登记订阅时指定的方案、扣费日等内容。
请重新登记订阅，并指定变更后要使用的方案和扣费日等信息。在首次扣费日前一天之前，可更改部分内容。
通过 API 更改登记内容时，请使用更新订阅 API。通过控制面板更改时，在订阅列表中找到对应订阅，点击该行右侧菜单，再选择“编辑”。

已设定给订阅的方案内容也无法更改。要更改方案内容，例如启用或停用重试，请新建一个包含更改内容的方案，并指定该方案登记新的订阅。

取消订阅

通过 API 取消时，请在取消订阅接口中指定要取消的订阅并执行。
通过控制面板取消时，在订阅列表中找到对应订阅，点击该行右侧菜单，再选择“取消订阅”。
自执行取消操作之日起，后续扣费日将停止处理扣费。
※即使取消了有待重试任务的订阅，取消时已安排的重试仍会执行完毕。
