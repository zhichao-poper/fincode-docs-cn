开发与监控

获取 API 密钥

访问 fincode API 时，使用为各商户账户签发的 API 密钥认证请求。缺少密钥、密钥错误或使用旧密钥时，都会返回错误。API 密钥分为测试环境密钥和生产环境密钥，可在控制面板查看。

从控制面板获取 API 密钥

使用 Webhook

商户账户发生支付等事件时，通知会发送至商户应用。Webhook 适用于支付状态变化之类的异步事件。

Webhook 也可在控制面板中设置。

事件列表和 Webhook 设置 API 的规范可在 API 参考中查看。

Webhook 规范

HTTP 请求

fincode 会按以下规范发送 HTTP 请求。

HTTP 方法格式
POSTJSON　　　　　　　

请求头

项目值
Fincode-Signature填入登记 Webhook 时为签名（signature）参数设置的值。
可用于识别来自 fincode 的通知。

其他

Webhook 通知通过 443 端口使用 HTTPS 发送。请指定能够接收此类通信的通知 URL。

Webhook 响应

商户需要回应 Webhook 请求，表明是否成功接收通知。如果返回接收失败，fincode 会按重试规范再次发送通知。Webhook 要求的 HTTP 响应如下。

响应头

项目值
Content-Typetext/plain 或 application/json

状态码与响应体

状态码Content-Type值行为
200text/plain0判定为处理成功，结束。
200application/json{"receive": "0"}判定为处理成功，结束。
200text/plain1判定为接收失败，重试请求。
200application/json{"receive": "1"}判定为接收失败，重试请求。
4xx, 5xx上述值以外的值上述值以外的值判定为错误，重试请求。
4xx, 5xx上述值以外的值上述值以外的值判定为错误，重试请求。

Webhook 重试规范

事件发生时，fincode 会向商户设置的 URL 发送 Webhook 请求。
如果该请求因错误失败，fincode 会重新发送 Webhook 请求。

重试规范说明
重试条件· 请求目标返回状态码为 4xx、5xx 的错误
· 请求目标返回的响应体不是 "0"
· 3 秒内未收到请求目标的响应
重试次数最多重试 5 次（含首次发送最多执行 6 次。）
重试间隔约 20 分钟
